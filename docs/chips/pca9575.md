# PCA9575 — NXP 16-bit I2C GPIO expander (×2 populated + 1 phantom)

- **Part:** NXP **PCA9575** — physical **UB1** (@0x20) + **U10** (@0x21).
- **Function:** GPIO expansion — HDD power/present/fault-LED, SFP straps/LED, board control.
- **Confirmed:** i2c-devices `nxp,pca9575 @ 0x20 / 0x21`; driver `pca953x`. ✅ live. (`@0x29` is
  a DT-only phantom — see below, not a third populated chip.)

## Key specs

- **I/O:** 16 configurable GPIO (2 banks of 8), default inputs at power-up.
- **Interface:** I²C, up to 400 kHz (100 kHz compatible).
- **Voltage: 1.1–3.6 V**, separate supply rails per I/O bank → built-in level translation. Very low standby (<2 µA).
- **Extras:** active-LOW `RESET` pin; open-drain `INT`; programmable pull-up/pull-down or bus-hold per pin; GPIO All-Call; polarity inversion.
- **Package:** TSSOP24 / TSSOP28 / HWQFN24. Only the 28-pin has 4 address pins (up to 16 devices).

## How it connects here

- **Bus:** on-SoC DesignWare I²C (i2c-0, parent) — [hardware.md#mmio-and-address-map](../hardware.md#mmio-and-address-map). Addresses 0x20, 0x21 (0x29 is a phantom, see below).
- **Driver:** `pca953x` (mainline).
- **Role / pin map — full, live-confirmed** (canonical: [i2c-map.md](../i2c-map.md),
  [dt-gaps-hardware-of-record.md](../dt-gaps-hardware-of-record.md) C4/C5,
  [sata-bay-power-ordering.md](../sata-bay-power-ordering.md)):
  - **@0x21 (bay control):** pins 0-3 = bay1-4 pwren (gpio 480-483, now `regulator-fixed`
    nodes gating AHCI probe, #104); pins 4-7 = bay presence (gpio 484-487, active-low);
    pins 12-15 = bay fault LEDs (gpio 492-495).
  - **@0x20 (SFP straps/LED):** pin 2 = `sfp_1g` link LED (gpio 498, active-high); pins
    12/14/15 = strap/status/present inputs (gpio 508/510/511, `lines-initial-states=0xd688`).
  - **@0x20 pins 3/7/9/10 — inputs, function genuinely unknown.** `lines-initial-states=0xd688`
    marks them as inputs but they're never exported to userland (unlike 12/14/15) and have
    **no software consumer found anywhere**, live or in source (2026-08-27 search):
    - U-Boot `dt_based_init_gpio_expander()` (`board/annapurna-labs/alpine_ubnt/board.c`) is
      fully DT-driven with no per-pin logic — the `0xd688` mask lives only in the flash
      board-cfg DTB, not in any GPL source tree.
    - Mainline kernel: only the generic `gpio-pca953x.c` driver, no board-specific consumer.
    - `ubnthal.ko` (decompiled prior session, see `docs/firmware-5.1.25.md`): board/SKU
      identity comes exclusively from the AT24C64 EEPROM @0x57, not any GPIO read — rules
      out "SKU strap via GPIO" as the vendor's mechanism.
    - Not yet decompiled for this specific question: `/sbin/ubnt-tools` (has `id`/`fwinfo`
      applets), and a re-run of `nm`/`objdump` on `ubnthal.ko`/`ustorage` targeted at
      `gpio`/`pca953x`/gpio 499,503,505,506 specifically (a prior pass covered these
      binaries but wasn't targeted at these 4 lines).
    - Best current guess: unused/reserved expander inputs or factory test points, not an
      active strap — but unconfirmed pending the above.

## ⚠ 0x29 is a phantom — DT-only, never populated on this board

- `pca953x 0-0029: failed reading register` / probe `-121` (EREMOTEIO) on **every** kernel incl. the live 5.1.25 capture (dmesg.txt:83). This is the **UDM-Pro's second bay-expander** (drives Pro bays 5-8) — correctly absent on the 4-bay ea16, not a fault or a wiring gap. DT node removed ([kernel-boot-fixes.md](../kernel-boot-fixes.md) Bug 3).
