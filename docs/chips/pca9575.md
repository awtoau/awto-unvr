# PCA9575 — NXP 16-bit I2C GPIO expander (×3)

- **Part:** NXP **PCA9575**.
- **Function:** GPIO expansion — HDD power/present, LEDs, board control. **Three** on board.
- **Confirmed:** i2c-devices `nxp,pca9575 @ 0x20 / 0x21 / 0x29`; driver `pca953x`. ✅ live.

## Key specs

- **I/O:** 16 configurable GPIO (2 banks of 8), default inputs at power-up.
- **Interface:** I²C, up to 400 kHz (100 kHz compatible).
- **Voltage: 1.1–3.6 V**, separate supply rails per I/O bank → built-in level translation. Very low standby (<2 µA).
- **Extras:** active-LOW `RESET` pin; open-drain `INT`; programmable pull-up/pull-down or bus-hold per pin; GPIO All-Call; polarity inversion.
- **Package:** TSSOP24 / TSSOP28 / HWQFN24. Only the 28-pin has 4 address pins (up to 16 devices).

## How it connects here

- **Bus:** on-SoC DesignWare I²C — [hardware.md#mmio-and-address-map](../hardware.md#mmio-and-address-map). Addresses 0x20, 0x21, 0x29.
- **Driver:** `pca953x` (mainline).
- **Role:** HDD power/LED control (per `ubnt-hdd-pwrctl` + linux-alpine-v2). **Pin map incomplete — only pins 4, 5, 8 known.** Note: HDD power actually uses SoC `gpio3:5`, not `pca9575:5` (see [sources.md](../sources.md)).

## ⚠ 0x29 is non-responsive

- `pca953x 0-0029: failed reading register` / probe `-121` (EREMOTEIO) on **every** kernel incl. the live 5.1.25 capture (dmesg.txt:83). Listed in the I²C table but 0x29 never probes — likely unpopulated or mux-hidden. Treat as 2 working + 1 phantom.

## RE / repurpose notes

- Register model = NXP PCA957x: config/input/output/polarity/pull/int-mask, 2 banks. `pca953x` handles it directly.
- To map the unknown pins: toggle outputs via `/sys/class/gpio` (gpiochip for each 0x20/0x21) and watch HDD power/LED behaviour — safer than guessing from the incomplete linux-alpine-v2 map.
- 1.1–3.6 V I/O — if driving anything externally, check the bank rail before wiring.
