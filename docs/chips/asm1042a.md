# ASM1042A — ASMedia USB 3.0 xHCI host

- **Part:** ASMedia **ASM1042A**.
- **Function:** PCIe-to-USB 3.0 xHCI host controller. Drives the internal boot USB stick.
- **Confirmed:** live `lspci` PCI `1b21:1142`, subsystem string ASM1042A; behind external-PCIe0. ✅ live.

## Key specs

- **Upstream:** PCIe Gen2 x1 (link: `PCIE_0: Link up. Speed 5GT/s Width x1`).
- **Downstream:** USB 3.0 SuperSpeed (5 Gbps) + USB 2.0.
- **PCI ID:** `1b21:1142` (vendor ASMedia `1b21`).
- **Package:** QFN (no public pinout).
- **Voltage:** core + I/O rails on-module (not board-programmable); details NDA.

## How it connects here

- **Bus:** external PCIe0 (`annapurna-labs,alpine-external-pcie` @ `0xfd800000`); the xHCI EP decodes at mem BAR `0xc0010000` (BDF `0001:01:00.0`). See [hardware.md#mmio-and-address-map](../hardware.md#mmio-and-address-map).
- **Driver:** `xhci_hcd` (mainline) — stock, no vendor glue needed.
- **Role:** the glued-down internal flash stick enumerates on this controller as **`/dev/sdq`** (SanDisk Ultra, USB3 SuperSpeed, `hcc params 0x0200e081`). Deliberately after `/dev/sd[a-p]` HDD slots.

## Datasheet

- **No public datasheet.** ASMedia distributes ASM1042A specs under NDA. Do not chase.
- Best public references: Linux `drivers/usb/host/xhci-pci.c` (ASMedia quirks), lsusb/lspci output, and ASMedia's public product brief.

## RE / repurpose notes

- Benign boot noise, both kernel generations: `AL PCIe bridge quirk detected, disable MSI(X)` on bus 0001 and an SR-IOV VF probe failure (`probe of 0001:00:00.0 failed with error -22`). Not a fault.
- Purely an accessory USB host — not part of the boot ROM chain. The boot *media* on it (the USB stick) is what boots; the controller is transparent.
