# Fedora shares, persistent mounts, network benches (#372)

- Measured 2026-11-17, woomera Fedora 7.4.0-rc2-perf-9b19c94+, box 10G `enp0s2` (74:ac:b9:41:a8:12, .127) <-> workstation `enp8s0` (Mellanox mlx4, 10000 Mb/s, 00:02:c9:56:ff:e2, .30).
- Setup is code: `./dev.py fedora-shares plan|apply [--i-accept-wipe]|verify` (`scripts/fedora-shares.py`). Idempotent; owns fstab lines, `/etc/exports.d/awto.exports`, `/etc/samba/smb.conf`, user `dan`.
- Box has no default route in the main table and no resolv.conf (multihome policy routing, #170): `dnf` needs a temporary `ip route add default via 192.168.25.254 metric 500` + `/run/NetworkManager/resolv.conf`. Packages: `nfs-utils samba samba-client cifs-utils`.

## Mounts (fstab by UUID, survives reboot, verified after one reboot 2026-11-17)
| path | fs | disks | opts |
|---|---|---|---|
| `/srv/mirror` | btrfs RAID1 data+meta, crc32c, label btrfs-test | WD82PURZ VGG8B0LG + VGG8ASZG | `noatime,space_cache=v2,nofail,x-systemd.device-timeout=30s` |
| `/srv/single` | btrfs `-d single -m dup`, crc32c, label single-5t | ST6000VX001 WCT3LCS1 (ZFS `tank` wiped) | same |
- Mirror UUID changes on every `bench-all --btrfs-config`; re-run `fedora-shares apply` afterwards (replaces the fstab line by mount point).
- Top dirs owned `dan:dan` (uid 1000; box user `dan` has no shell/home).
- `/mnt/btrfs-test` is retired; `bench-all` default is `/srv/mirror`.

## Firewall / SELinux
- SELinux: Disabled. No firewalld, no nftables/iptables binaries, no `nf_tables`/`ip_tables` in the kernel: nothing filters. Access control = smb `hosts allow` + export subnet only.

## SMB (works)
- `smb.conf`: SMB3 only (`server min protocol = SMB3`), no guest (`map to guest = Never`), `valid users = dan`, `hosts allow = 127. 192.168.25.`, `disable netbios = yes` (nmb not enabled: SMB over 445 needs no NetBIOS).
- Shares `mirror`, `single` only (system drive is not shared over SMB). `smb` enabled at boot.
- Password: `~/.config/awto/secrets.yaml` section `woomera-fedora-smb` (generated by apply, never printed).
- Client used for benches: `mount -t cifs` (cifs-utils) `vers=3.1.1`, credentials file in `tmp/` removed after mount; verify uses `smbclient -A`.

## NFS (BLOCKED: kernel has no NFSD)
- Fedora config `unvr-ea16-7.4-fedora.config` has `# CONFIG_NFSD is not set`, `# CONFIG_NFS_FS is not set`, no SUNRPC (`unvr_defconfig` has `NFSD=m`, the Fedora build does not use it). `nfs-server` fails on `proc-fs-nfsd.mount: unknown filesystem type 'nfsd'`.
- Staged, not active: `/etc/exports.d/awto.exports` (written by apply): `/`, `/srv/mirror`, `/srv/single` to `192.168.25.0/24`, `rw,sync,no_subtree_check,root_squash,fsid=1..3`, no `crossmnt`.
  - `root_squash`: client root is mapped to nobody, so root-owned files on `/` cannot be changed from clients; client uid 1000 = box `dan` (uid 1000) can write only where `dan` has permission (`/var/tmp`, `/srv/*`).
  - Flat NFSv4 exports (no `fsid=0` pseudo-root): clients mount `host:/srv/mirror` directly; `host:/` does not show the data mounts (no crossmnt).
- Needs a kernel change (`NFSD=m` + `SUNRPC` + `LOCKD` + `NFSD_V4`): decision for Dan. `apply` enables `nfs-server` automatically once the kernel registers `nfsd`; `bench-all --nfs` runs the same jobs as `--smb`.
- `var-lib-nfs-rpc_pipefs.mount` shows failed in `systemctl --failed` for the same reason.

## Network ceiling (iperf3 3.x, `--bind-dev enp8s0`, 10 s, 2026-11-17)
| streams | host -> box | box -> host |
|---|---|---|
| 1 | 1162 MB/s (9293 Mb/s), box cpu 83% | 582 MB/s (4660 Mb/s) |
| 4 | 1165 MB/s (9317 Mb/s), box cpu 125% (of 400) | 822 MB/s (6574 Mb/s) |
- NIC: traffic on box `enp0s2` (`ip neigh` MAC 74:ac:b9:41:a8:12 matched on host) and host `enp8s0` (counter deltas in snapshot `bench-20261117-net-ceiling.json` info). `enp0s1` has no carrier; USB NICs absent.
- Box transmit path is the weaker direction (582-822 MB/s): a read from the box can reach at most ~0.6-0.8 GB/s, far above any disk here.
- Strict ARP + per-NIC route tables from `scripts/fix-multihome-routing.py` are applied on Fedora via `/etc/NetworkManager/dispatcher.d/90-awto-multihome` (arp_ignore=1 confirmed after reboot).

## SMB benches (cifs 3.1.1 mounted on workstation, fio direct=1 libaio, 4 GiB file, caches dropped both ends, 2026-11-17)
| target | seq write 1M QD4 | seq read 1M QD4 | randread 4k QD16 | randwrite 4k QD16 | small create 4 KiB x5000 | small read |
|---|---|---|---|---|---|---|
| mirror | 241.0 MB/s (box cpu 22%, host 7%) | 266.7 MB/s (22%, 6%) | 345 iops (box 2%) | 11588 iops (box 55%) | 391 files/s | 753 files/s |
| single | 182.6 MB/s (17%, 7%) | 198.3 MB/s (16%, 7%) | 343 iops | 11608 iops (box 58%) | 386 files/s | 699 files/s |
- Local reference, same disk, same job (direct, QD4, 4 GiB): mirror 253.7 write / 271.0 read MB/s (`docs/btrfs-mirror.md`); single 195 write / 201 read MB/s (2026-11-17, fio on the box).
- SMB reaches 95-99% of local sequential throughput: the disk is the bottleneck, not the network (ceiling 1160 MB/s) nor box cpu (<=22%).
- Random 4k reads: 343-345 iops = disk seek rate (local mirror 181-329 iops); not network bound.
- Random write ~11.6k iops on both: absorbed by btrfs/page cache on the box (end_fsync after); box cpu 55-58% is the limit, not the disk. Not comparable to raw disk iops.
- Small files: ~390 creates/s, ~700-750 reads/s: per-file SMB round trips (latency bound), cpu low on both ends.
- System SSD over NFS: not measured (NFS blocked). `--share-targets` includes `system` for NFS only.

## Read spreading on the mirror (kernel read_policy `pid`; 2026-11-17)
- `read_policy` sysfs is absent on this kernel (no `CONFIG_BTRFS_EXPERIMENTAL`): fixed `pid` policy (reader pid parity picks the mirror). round-robin/devid unavailable without a kernel rebuild.
- fio direct 1M QD4 sequential, N readers on N separate 4 GiB files, 20 s, 3 runs each, per-disk from `/proc/diskstats`:
| readers | aggregate MB/s (3 runs) | per-disk MB/s (sda / sdb) |
|---|---|---|
| 1 | 248.5, 253.0, 248.4 | 249 / 0, 253 / 0, 249 / 0 |
| 2 | 483.6, 494.5, 498.9 | 234 / 250, 241 / 254, 236 / 263 |
| 4 | 143.9, 125.8, 96.8 | 95 / 50, 65 / 61, 51 / 47 |
- Conclusion: one reader uses one disk (~250 MB/s). Two readers landed on different disks all 3 runs (pid parity luck, not guaranteed) and doubled to ~490 MB/s. Four readers collapse to 97-144 MB/s: two streams per disk seek between files (HDD seek thrash), not a cpu limit (cpu 2-3%).
- Reads are spread only across independent readers, and only when their pids differ in parity; a single stream never exceeds one disk. Over SMB/NFS from one client the server has smbd/nfsd pids per connection: expect single-disk speed.
